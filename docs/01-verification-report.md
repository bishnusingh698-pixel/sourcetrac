## Conflicts with your prompt (research wins)

1. **Billing — biggest change.** Your prompt says "Use Shopify billing only." Shopify's current guidance splits this:
   - **Shopify App Pricing** is now the *default and preferred* path, and as of **2026-04-28** it **stopped sending billing webhooks** and stopped passing `charge_id`. Reading subscription state now requires a **Partner API** client with org-level "Manage apps" permission (4 req/s limit).
   - **Shopify Billing API** (`appSubscriptionCreate`) is still **supported**, explicitly for "existing apps and outlier pricing models Shopify App Pricing doesn't cover", and `replacementBehavior` cleanly handles upgrade/downgrade.
   - **Decision:** I am implementing the **Shopify Billing API**, as you asked. This is compliant with requirement 1.2.1 and is simpler than App Pricing here because your three plans are flat recurring subscriptions with no usage metering. **You can switch to Shopify App Pricing later** — it requires no code rewrite of the admin UI, only replacing the subscription-status check. This is documented in the logic spec.

2. **Polaris — changed.** Your prompt says "Current Polaris components only." Polaris **React** is deprecated and archived. Current = **Polaris Web Components** (`s-*` tags). I'm building the admin UI with web components.

3. **One extension or two — changed.** Your prompt implies one extension. `purchase.thank-you.block.render` is a Checkout UI Extension; `customer-account.order-status.block.render` is a Customer Account UI Extension. I will ship **two extension directories**. Shopify's tutorial puts both in one checkout_ui folder, but the Customer Account target is documented in a separate API namespace, and shipping them separately matches the docs and avoids config risk. Functionally identical for the buyer.

4. **"Custom branding" in the survey — narrowed.** You asked me to say what "custom branding" can realistically mean. Shopify docs are explicit: "You can't override the CSS for UI components. The checkout UI will always render the merchant's own branding." So real customisation reduces to: **question text, option labels, emoji, and layout choice among the provided components.** Fonts, colours, and spacing are inherited automatically from the merchant's checkout branding. I will document this honestly in Settings and in the listing, and **not** offer a colour picker.
